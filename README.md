# Моё Радио — PWA

Мобильное веб-приложение интернет-радио без серверной части.

## Возможности
- каталог Radio Browser API;
- поиск станций;
- категории: популярное, Россия, Германия, рок, электроника, джаз, chillout, новости;
- крупные карточки популярных российских станций;
- избранное;
- история прослушивания;
- название трека, исполнитель и доступное время текущего трека;
- добавление собственных потоков;
- таймер сна;
- эквалайзер с пресетами для CORS-совместимых потоков;
- Media Session (экран блокировки/гарнитура — когда браузер поддерживает);
- PWA и добавление на главный экран iPhone/Android;
- офлайн-кэш оболочки приложения (само радио требует интернет).

## Запуск локально
Не открывайте `index.html` напрямую через `file://`: для PWA и части сетевых функций нужен HTTP(S).

Пример:
```bash
python3 -m http.server 8080
```
После этого откройте `http://localhost:8080`.

## Установка на iPhone
1. Опубликуйте папку на HTTPS-хостинге.
2. Откройте адрес в Safari.
3. Нажмите «Поделиться» → «На экран Домой».

## Важно про эквалайзер
Браузерный Web Audio может обрабатывать только потоки, которые разрешают CORS. Если конкретная станция этого не разрешает, приложение автоматически продолжит обычное воспроизведение без EQ.

### Обновление v12
- Запуск DnB после паузы вызывает `play()` в исходном нажатии, без задержки. Запоздавшие результаты старого запуска не меняют новую станцию; переподключения ограничены.
- Проверка зависания учитывает реальное движение `currentTime`, даже если браузер редко отправляет `timeupdate` в фоне. Исправный поток не перезапускается при возвращении на экран.
- Смена категории и очистка поиска отменяют старые запросы и отложенный поиск. Некорректный ответ одного зеркала не блокирует исправное зеркало.
- Плеер показывает трек и исполнителя; если станция сообщает время начала и длительность, показывает прошедшее время и прогресс. Трек также передаётся в Media Session.
- Обновление PWA заменяет только собственный кэш радио. Ключи и форматы избранного, истории, собственных станций и настроек сохранены.

### Данные текущего трека
Приложение читает публичные HTTPS API AzuraCast, Icecast и Shoutcast на сервере выбранного потока. Сервер должен разрешать браузерные запросы через CORS. AzuraCast с адресами `/listen/{station}/…` может передавать `played_at`, `duration` и `elapsed`; Icecast часто передаёт только строку `Исполнитель - Трек`. На общем сервере данные сопоставляются с адресом выбранной станции.

Не все радиостанции публикуют эти данные. Во время DJ-эфира может передаваться название передачи или микса. Приложение не выдумывает исполнителя, начало или длительность; при отсутствии ответа показывает «Данные о треке недоступны». Время соединения с сервером не считается временем начала песни. Метаданные запрашиваются отдельно от звука: ошибка API не прерывает воспроизведение. При паузе и скрытом экране запросы прекращаются, при возвращении данные обновляются.

Названия обновляются каждые 15 секунд при открытом приложении. Время берётся из эфирных данных станции; буферизация звука может дать расхождение с услышанным моментом. При скрытом приложении на экране блокировки остаётся название станции, чтобы не выдавать устаревшую песню за текущую. Постоянное отображение точного трека для всех станций, в том числе в фоне, статический веб-плеер гарантировать не может.

Документация формата AzuraCast: https://azuracast.com/docs/developers/now-playing-data/.

### Проверка изменений
Регрессионные сценарии без дополнительных зависимостей (Node.js 18+):
```bash
node --test tests/*.test.cjs
```
Тесты проверяют гонки запуска и поиска, длительные паузы с управляемыми часами, ограничение повторов, правильность метаданных, отсутствие ложного времени и сохранность чужого кэша. Это проверки с моделируемыми ответами, а не подключение ко всем публичным станциям.

Перед выпуском проведена отдельная проверка Chromium с мобильным viewport, декодируемым WAV-потоком и управляемыми API: шесть циклов паузы/запуска, обновление трека, ошибка метаданных без остановки звука, длинные названия, сохранность избранного/собственных станций/истории, обновление Service Worker v11 → v12 и офлайн-оболочка. Физический iPhone/Safari, звонки, доступность станций и API в сети пользователя, работа с VPN и энергопотребление требуют проверки на устройстве.
